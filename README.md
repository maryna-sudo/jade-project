# JADE Project and Task Flow Management

Цей проєкт реалізує навчальну багатоагентну систему на базі **JADE** для:

- управління проєктами;
- управління потоком задач;
- проектування агентно-орієнтованих задач на основі технології програмних агентів.

На відміну від базового прикладу торгівлі книгами, тут реалізовано сценарій, у якому агент-координатор керує проєктами, розподіляє задачі між агентами-виконавцями та відстежує їх проходження через фіксований workflow.

## Що є в проєкті

- `ProjectCoordinatorAgent` зберігає проєкти й задачі в пам'яті, призначає задачі та контролює їх завершення.
- `TaskWorkerAgent` реєструє сервіс виконання задач, приймає призначення, переводить задачі в `IN_PROGRESS` і завершує їх у стані `DONE`.
- `MonitoringAgent` отримує події від координатора та виводить журнал виконання.
- `scripts/linux/` містить сценарії компіляції й запуску для Linux/macOS.
- `scripts/windows/` містить сценарії компіляції й запуску для Windows `cmd`.

## Архітектура агентів

У проєкті використовуються три ролі агентів:

1. `ProjectCoordinatorAgent`
2. `TaskWorkerAgent`
3. `MonitoringAgent`

Координатор використовує `DFService` для пошуку виконавців із сервісом `task-execution`, після чого розподіляє між ними задачі за принципом `round-robin`.

## Workflow задач

Кожна задача проходить такі стани:

`TODO -> IN_PROGRESS -> DONE`

Стан `TODO` означає, що задача створена, але ще не виконується.  
Стан `IN_PROGRESS` встановлюється агентом-виконавцем після прийняття задачі.  
Стан `DONE` означає завершення виконання і повідомляється координатору через ACL-повідомлення.

## Вимоги

- Java JDK 21 або сумісна версія з `javac`
- локальний файл `lib/jade.jar`

## Структура

```text
.
├── lib/jade.jar
├── scripts/linux/
├── scripts/windows/
├── src/com/example/jade/projectmanagement/
├── README.md
```

## Компіляція

Linux / macOS:

```bash
chmod +x scripts/linux/*.sh
./scripts/linux/compile.sh
```

Windows (`cmd`):

```bat
scripts\windows\compile.bat
```

Після компіляції `.class` файли з'являться в каталозі `bin/`.

## Запуск демонстраційного сценарію

Спочатку запустіть платформу з моніторингом і виконавцями:

Linux / macOS:

```bash
./scripts/linux/start-platform.sh
```

Windows (`cmd`):

```bat
scripts\windows\start-platform.bat
```

Цей сценарій запускає:

- `monitor`
- `worker1`
- `worker2`
- `worker3`

Потім окремо запустіть координатора в іншому контейнері:

Linux / macOS:

```bash
./scripts/linux/start-coordinator.sh
```

Windows (`cmd`):

```bat
scripts\windows\start-coordinator.bat
```

## Очікувана поведінка

- агенти-виконавці реєструються в `Directory Facilitator`
- координатор створює демонстраційні проєкти й задачі
- координатор знаходить агентів-виконавців через `DF`
- задачі розподіляються між виконавцями
- виконавці повідомляють про перехід у `IN_PROGRESS`
- після затримки-імітації виконавці переводять задачі у `DONE`
- координатор фіксує завершення всіх задач у проєкті
- `MonitoringAgent` веде журнал подій

## Що демонструє цей приклад

- створення спеціалізованих агентів у JADE
- управління проєктами через центрального агента-координатора
- управління потоком задач через фіксований workflow
- пошук сервісів через `DFService`
- взаємодію агентів через `ACL`-повідомлення
- агентно-орієнтоване проектування системи з розподілом ролей

## Параметри агентів

`TaskWorkerAgent` може приймати один необов'язковий параметр: затримку виконання в мілісекундах.

Приклад:

```text
worker1:com.example.jade.projectmanagement.TaskWorkerAgent(2000)
```

`ProjectCoordinatorAgent` у поточній версії запускається без обов'язкових аргументів і самостійно створює демонстраційні проєкти.
